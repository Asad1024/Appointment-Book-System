1. EXECUTIVE SUMMARY
================================================================================

Slotwise is a production-grade appointment booking platform for companies that
need public scheduling, staff administration, product integrations, and customer
self-service.

Brand name:     Slotwise
Tagline:        Appointment scheduling platform
Description:    Book demos, manage team availability, and integrate scheduling
                across your products.

The system is split into:
  - apps/web     → Next.js 14 (App Router) frontend on port 3000
  - apps/api     → NestJS REST API on port 3001
  - packages/scheduling-core → Slot generation (Luxon)
  - packages/shared-types    → Shared enums and TypeScript types

Core capabilities:
  - 5-step public booking wizard (service → provider → slot → details → confirm)
  - Guest booking OR registered customer accounts
  - Magic-link appointment management (cancel / reschedule / .ics download)
  - Staff admin portal with dashboard, catalog, availability, team, settings, reports
  - Product integration via URL params, iframe embed, webhooks, return URLs
  - Email confirmations and automated reminders (24h and 1h)
  - Overlap protection with MySQL row locking
  - CSRF protection, JWT httpOnly cookies, role-based access control
  - Waitlist when slots are taken
  - Swagger API docs at /api/docs

5. HOW THE APPLICATION WORKS (END-TO-END)
================================================================================

PUBLIC BOOKING FLOW
-------------------
1. User visits /book (optionally with ?product=, ?source=, ?campaign=, ?returnUrl=)
2. Frontend calls GET /integration/context?org=demo-company&product=...
   → Returns branding, location, filtered services
3. User walks through 5 wizard steps (state persisted in sessionStorage)
4. For each date, frontend calls GET /availability/slots with location, service,
   provider, date range
5. On confirm, POST /appointments/book with idempotency key
6. API validates slot, locks rows, creates appointment + customer record,
   sends confirmation email, fires webhook
7. User sees success screen with link to /manage/[manageToken]
8. If returnUrl provided, redirects after 2 seconds with ?booked=true&appointmentId=

CUSTOMER ACCOUNT FLOW
---------------------
1. User registers at /register → POST /auth/register
2. Verification email sent → user visits /verify-email or link with token
3. User signs in at /login → JWT cookies set
4. Customer redirected to /account (staff redirected to /admin/dashboard)
5. /account lists paginated appointments from GET /auth/me/appointments

MAGIC LINK MANAGEMENT
---------------------
1. Confirmation email contains link to /manage/[token]
2. No login required — token is the credential
3. User can view details, download .ics, reschedule (max 3 times), or cancel
4. Cancellation respects location cancellationCutoffH policy

STAFF ADMIN FLOW
----------------
1. Staff signs in at /login (same page as customers)
2. Role detected → redirect to /admin/dashboard
3. useStaffSession hook guards all /admin/* routes
4. Admin manages services, providers, schedules, appointments, team, settings
5. Org admins see Team and Settings nav items; other staff roles may not

TEAM ONBOARDING
---------------
1. Org admin invites colleague at /admin/team
2. API creates TeamInvite with token → returns acceptUrl
3. Invitee opens /invite/[token], sets name + password
4. POST /team/invites/token/:token/accept → user created with assigned role

  GET  /admin/settings            Branding + location policies (org admin)
  GET  /admin/team                Invite members, pending invites (org admin)

  (implicit) not-found            Custom 404 page
  (implicit) error                Global error boundary

QUERY PARAMETERS ON /book AND /embed/book
  org         Organization slug (default: demo-company)
  product     Filters services by productKey
  source      Attribution stored on appointment
  campaign    Marketing campaign id
  returnUrl   HTTPS URL to redirect after booking
  embed       Set internally on embed route (source = 'embed')

QUERY PARAMETERS ON /login
  next        Safe relative redirect after login (e.g. /admin/dashboard)

BASE URL: process.env.NEXT_PUBLIC_API_URL ?? 'http://localhost:3001'

FUNCTIONS:
  getApiUrl()         Returns API base
  ensureCsrf()        Fetches GET /auth/csrf, caches token
  api<T>(path)        Generic fetch with credentials + CSRF on mutations
  apiAuth<T>(path)    Alias for api (session via cookies)
  logout()            POST /auth/logout, clears CSRF cache
  fetchMe()           GET /auth/me → AuthUser

CSRF:
  - Required on POST, PATCH, PUT, DELETE
  - Header: x-csrf-token
  - Cookie-based validation on API

ERROR HANDLING:
  - 401 → "Session expired. Please sign in again."
  - 403 → Access denied with API message
  - Other → Parses NestJS { message: string | string[] }

AUTH USER TYPE:
  { id, email, name, role, emailVerified }

HOOKS:
  useAuthUser.ts    → /auth/me for public header (all roles)
  useStaffSession.ts → staff-only guard for /admin layout

    - Calls fetchMe()
    - If role not in STAFF_ROLES → redirect /login?next=<current path>
    - While loading → full-screen skeleton

ORG ADMIN CHECK
  isOrgAdmin = role === 'org_admin' || role === 'super_admin'
  Hides /admin/settings and /admin/team from sidebar for other roles

API RolesGuard
  Decorator @Roles(...) on controller methods
  Compares req.user.role against required roles

14. CUSTOMER USER OPERATIONS
================================================================================

GUEST BOOKING (no account)
  1. Go to /book
  2. Complete wizard with name + email
  3. Receive confirmation email with /manage/[token] link

RESCHEDULE (customer)

  - Blocked if within cancellation cutoff window

CANCEL (customer)
  - Open manage link → Cancel appointment → Confirm dialog
  - Blocked if status is cancelled/completed
  - Blocked if within cancellationCutoffH hours of start time

ADD TO CALENDAR
  - Downloads .ics file client-side (no API call)

WAITLIST
  - If slot taken during booking, "Join waitlist" button appears
  - POST /appointments/waitlist with email, name, preferred date

16. BOOKING WIZARD (DEEP DIVE)
================================================================================

Component: components/BookingWizard.tsx

STEPS (0-indexed):
  Step 0: Service     — list services from integration context
  Step 1: Provider   — specific provider OR "Any available provider"
  Step 2: Date/time  — DateTimePicker with slot grid
  Step 3: Details    — name, email, phone (react-hook-form + zod)
  Step 4: Confirm    — review summary → submit

STATE PERSISTENCE:
  sessionStorage key: 'slotwise_booking_wizard'
  Saves: step, serviceId, providerId, selectedDate, startUtc, timezone, locationId
  Cleared on successful booking

INTEGRATION CONTEXT LOAD:
  GET /integration/context?org=demo-company&product=...
  Returns: { branding, location, services[], product }
  If only 1 service → auto-select and jump to step 1

PROVIDER LOAD:
  GET /catalog/locations/:locationId/providers?serviceId=&product=

SLOT LOAD:
  GET /availability/slots?locationId&serviceId&providerId&fromDate&toDate

BOOKING SUBMIT:
  POST /appointments/book
  Body: locationId, serviceId, providerId, startUtc, customerName, customerEmail,
        customerPhone?, customerTimezone, idempotencyKey (UUID),
        product, campaign, source, returnUrl, metadata (JSON string)
  Pre-submit: re-fetches slots to verify availability (optimistic concurrency)

SUCCESS STATES:
  A) Normal: AnimatedCheckmark + manage link + account link
  B) Pending approval (requiresApproval services): hourglass + pending message
  C) With returnUrl: redirect after 2s with query params

WAITLIST:
  Triggered when slot conflict detected (slotUnavailable flag)
  POST /appointments/waitlist

UI ELEMENTS:
  - Progress bar (width = (step+1)/5 * 100%, uses org primaryColor)
  - StepIndicator pills
  - BookingSummaryPanel in right column (desktop)
  - Framer Motion step transitions

Waitlist

25. SECURITY FEATURES
================================================================================

  - bcrypt password hashing
  - JWT in httpOnly cookies (not localStorage)
  - CSRF protection on all mutations
  - CORS restricted to CORS_ORIGIN env (default localhost:3000)
  - Rate limiting on API (configured in app module)
  - RBAC via RolesGuard + @Roles decorator
  - Open redirect prevention (sanitizeNextPath — only relative paths)
  - Idempotency keys on booking (prevent double-submit)
  - MySQL row locking for concurrent booking attempts
  - Webhook HMAC signature verification
  - Public manage tokens (unguessable UUIDs)
  - ValidationPipe with whitelist on all DTOs
